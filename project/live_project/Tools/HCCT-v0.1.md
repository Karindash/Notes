# Human Cognitive Capability Taxonomy (HCCT)

> \[!abstract\] Purpose HCCT is an exploratory framework for mapping the
> diverse capabilities humans use to perceive information, process
> situations, make decisions, learn, act, and adapt.
>
> **Version:** 0.1\
> **Status:** Initial conceptual baseline\
> **Next step:** Refine the primitive operations and validate the
> relationships between branches.

## 1. Working definition

For this project, *human cognitive capability* refers to the set of
mental and behavioral capabilities through which a person receives and
interprets stimuli, retains and transforms information, reasons about
situations, evaluates alternatives, makes decisions, executes actions,
learns, and adapts to changing circumstances.

This is a working definition, not a finalized scientific definition. The
framework is intended to become operational: each capability should
eventually have a clear definition, observable indicators, assessment
tasks, and interpretation rules.

## 3. Architecture and terminology

The current framework uses three conceptual levels:

  -----------------------------------------------------------------------
  Level                   Meaning                 Example
  ----------------------- ----------------------- -----------------------
  **Primitive operation** A broad foundational    Memory
                          cognitive operation or  
                          function                

  **Sub-capability**      A more specific         Working memory
                          capability associated   
                          with an operation       

  **Composite ability**   A capability that       Tactical
                          emerges from multiple   decision-making
                          operations working      
                          together                
  -----------------------------------------------------------------------

These levels are provisional. The taxonomy must not assume that every
branch is independent or that every item belongs at its current level.

### 3.1 Primitive operations

The initial core groups are:

1.  Perception
2.  Attention
3.  Memory
4.  Information Processing
5.  Reasoning
6.  Decision Making
7.  Execution
8.  Adaptation

### 3.2 Additional cognitive functions

The following are currently listed separately because their position in
the taxonomy needs further examination:

-   Learning
-   Prediction
-   Simulation
-   Inhibition
-   Metacognition
-   Association

They may turn out to be foundational operations, cross-cutting
functions, or composite processes involving several core groups.

### 3.3 Composite abilities

Composite abilities describe real-world performance that may depend on
several capabilities at once. Examples include:

-   Tactical decision-making
-   Strategic planning
-   Problem-solving
-   Creative problem-solving
-   Skill transfer
-   Complex situation management

A composite ability should eventually be mapped to the specific
sub-capabilities that contribute to it.

## 4. Illustrative use case: choosing and learning a game

Consider a person deciding whether to play a game they have never tried.

The decision may involve:

1.  **Preference retrieval:** recalling what kinds of games they enjoy.
2.  **Mechanic recognition:** identifying the game's rules and gameplay
    demands.
3.  **Skill mapping:** comparing those demands with skills they already
    possess.
4.  **Transfer estimation:** estimating which skills from familiar games
    may transfer.
5.  **Learning-cost estimation:** estimating the effort required to
    learn unfamiliar mechanics.
6.  **Reward prediction:** estimating the likely enjoyment or
    satisfaction.
7.  **Choice selection:** choosing whether to play, postpone, or select
    another game.

This example illustrates why a real-world ability should not
automatically be treated as a single intelligence. It may be a composite
of memory, perception, reasoning, prediction, decision-making, and
learning.

For example, experience in a real-time strategy game may help someone
recognize resource trade-offs in another strategy game. It does not
necessarily provide the reflexes or motor precision required in a
competitive shooter.

## 5. Methodological principles

The framework should follow these principles as it develops:

-   **Operational clarity:** every capability needs a precise
    definition.
-   **Observable evidence:** assessment should rely on behavior, task
    performance, or demonstrable outcomes rather than impression alone.
-   **Discriminant clarity:** neighboring capabilities should be
    distinguishable where possible.
-   **Context awareness:** performance should be examined across
    relevant contexts, not inferred from one isolated task.
-   **Reproducibility:** assessment procedures should be consistent
    enough to support meaningful comparison.
-   **Non-hierarchical interpretation:** a higher score in one
    capability does not make a person globally superior.
-   **Uncertainty awareness:** insufficient evidence must be recorded as
    unknown or unassessed, not treated as low ability.
-   **Construct separation:** distinguish capability from knowledge,
    experience, motivation, opportunity, and temporary state.

## 6. Development roadmap

Use this roadmap to evolve the framework incrementally. Do not add
scoring before the taxonomy and definitions are sufficiently stable.

### Phase 1 --- Primitive review

-   [ ] Define what qualifies as a primitive operation.
-   [ ] Review the eight initial core groups.
-   [ ] Decide whether any groups should be split, merged, renamed, or
    removed.
-   [ ] Examine whether the six additional functions are primitives or
    cross-cutting processes.
-   [ ] Identify missing foundational operations.
-   [ ] Record overlaps and unresolved classification questions.

**Deliverable:** a reviewed list of primitive operations with inclusion
criteria.

### Phase 2 --- Sub-capability decomposition

For each primitive:

-   [ ] Write a concise definition.
-   [ ] Identify its sub-capabilities.
-   [ ] Distinguish closely related terms.
-   [ ] Add examples from everyday life, work, games, learning, and
    unfamiliar situations.
-   [ ] Identify capabilities that may belong under more than one
    parent.

**Deliverable:** a detailed taxonomy with definitions and examples.

### Phase 3 --- Composite ability mapping

-   [ ] Select real-world tasks and situations.
-   [ ] Decompose each task into contributing sub-capabilities.
-   [ ] Map dependencies and interactions.
-   [ ] Distinguish necessary capabilities from helpful but optional
    ones.
-   [ ] Identify context-specific demands.

**Deliverable:** composite-ability maps and capability dependency
diagrams.

### Phase 4 --- Measurement design

For each selected sub-capability:

-   [ ] Define observable indicators.
-   [ ] Design one or more assessment tasks.
-   [ ] Specify scoring criteria and anchors.
-   [ ] Define how context, prior experience, and motivation are
    handled.
-   [ ] Record confidence and evidence quality.
-   [ ] Test whether different tasks produce consistent interpretations.

**Deliverable:** an assessment catalogue and scoring rubric.

### Phase 5 --- Validation and refinement

-   [ ] Pilot the assessment tasks.
-   [ ] Check whether the tasks measure the intended capability.
-   [ ] Examine reliability across repeated assessments.
-   [ ] Examine whether neighboring capabilities can be distinguished.
-   [ ] Review cultural, educational, language, and experience-related
    biases.
-   [ ] Revise definitions, tasks, and scoring rules.

**Deliverable:** a tested and revised framework. Until this phase is
complete, scores should be treated as exploratory rather than validated
measures.

### Phase 6 --- Individual capability profile

Only after earlier phases:

-   [ ] Aggregate evidence by sub-capability.
-   [ ] Represent unassessed areas separately from low scores.
-   [ ] Show strengths, development areas, and uncertainty.
-   [ ] Avoid collapsing the profile into one overall intelligence score
    unless there is a defensible reason.
-   [ ] Explain which contexts each capability profile does and does not
    predict.

**Deliverable:** a multidimensional capability profile.

## 8. Working rules for future revisions

1.  Do not add a new category merely because it sounds like a type of
    intelligence. Define what it measures.
2.  Do not assume that a familiar psychological term is automatically a
    primitive.
3.  When two categories overlap, document the overlap before deciding
    whether to merge or separate them.
4.  Use real-world examples to test whether a proposed distinction is
    meaningful.
5.  Keep the taxonomy descriptive before making it evaluative.
6.  Treat the framework as a developing conceptual model, not a
    clinically or scientifically validated intelligence test.
